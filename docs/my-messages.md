# 내 메시지 — 사용자 맞춤형 상황 공유 설계와 구현 범위

기본 상황 공유 버튼 4개(졸려요 · 쉬었다 갈까요? · 화장실 급해요 · 주유·충전)는 그대로 두고,
사용자가 휴대폰에서 직접 만든 문장을 **‘내 메시지’** 로 최대 6개 등록해 차량에서 한 번에 보낸다.
받는 차에서는 “민지님이 메시지를 보냈어요. 카페 들렀다 가요.”처럼 읽어 준다.

## 1. 구조 한눈에

```
[휴대폰] 내 메시지 관리 ──저장──▶ [계정 서버] ──동기화──▶ [차량 앱] 내 메시지 목록(읽기 전용)
                                                            │ 고르기(큰 버튼 1번)
                                                            ▼
[차량 앱] GroupMessage(Custom: 메시지 id · 문장 · 아이콘 · 보낸 사람) ─▶ GroupChannel.send ─▶ 모임 참여자에게만
                                                            ▲
                기본 상황 공유(Status) · 음성으로 상황 공유(Voice)도 같은 통로
```

- **같은 전송 시스템**: `domain/GroupMessage.kt` 의 `Status` / `Custom` / `Voice` 세 종류가 같은 `GroupChannel` 로 오간다.
  기본 메시지는 쉬어가기 투표까지 이어지고, 내 메시지·음성 메시지는 알림과 읽어 주기만 한다.
- **보내는 쪽은 글자와 보낸 사람만** 보낸다. 음성 파일을 만들어 보내지 않고, 받는 차가 자기 음성 엔진으로 읽는다.
- **기본 메시지와 내 메시지 구분**: 기본 메시지는 지우거나 고칠 수 없고(투표·추천과 연결), 내 메시지는 사용자 것이다.

## 2. 휴대폰 — 내 메시지 관리 화면 (설계)

휴대폰 앱은 아직 없어서 화면 설계만 둔다. 차량 앱의 데이터 모양(`QuickMessage`)과 검사 규칙(`QuickMessagePolicy`)을 그대로 쓴다.

### M-20 내 메시지 목록

```
┌ 내 메시지 ───────────────────────── 편집 ┐
│ 차량 화면에서 한 번 누르면 모임에 보내요      │
│                                            │
│ 기본 메시지 (고칠 수 없어요)                  │
│  🌙 졸려요      ☕ 쉬었다 갈까요?            │
│  🚻 화장실 급해요 ⛽ 주유·충전   🔒           │
│                                            │
│ 내 메시지 4/6                                │
│  ≡ [커피] 카페 들렀다 가요            ›  🗑  │
│  ≡ [사진] 사진 찍고 갈게요            ›  🗑  │
│  ≡ [천천히] 조금 늦을 것 같아요        ›  🗑  │
│  ≡ [밥] 점심은 휴게소에서 먹어요       ›  🗑  │
│                                            │
│ [ + 메시지 만들기 (4/6) ]                    │
│ 마지막 동기화 08:02 · 차량 2대               │
└────────────────────────────────────────────┘
```

- `≡` 를 끌어서 순서를 바꾼다. 차량 화면의 버튼 순서와 같다.
- 6개가 되면 ‘만들기’ 버튼이 잠기고 “6개까지 만들 수 있어요”를 보여 준다.
- 지우기는 한 번 더 묻는다(“이 메시지를 지울까요?”). 지운 뒤 5초 동안 ‘되돌리기’.

### M-21 메시지 만들기·고치기

```
┌ ‹  메시지 만들기 ─────────────── 저장 ┐
│ 아이콘                                  │
│ [☕][🍚][⛽][⚡][🚻][📷][🐢][⏰][👍][🅿][♪][☀] │
│ 문장                                    │
│ [ 카페 들렀다 가요            ] 9/20     │
│ ✓ 2~20자 · 글자·숫자·기본 문장부호        │
│ [ ▶ 미리 듣기 ]  “민지님이 메시지를 보냈어요. │
│                   카페 들렀다 가요.”       │
└────────────────────────────────────────┘
```

- 입력하면서 바로 검사한다(아래 5장). 문제가 있으면 저장 버튼을 잠그고 이유를 한 줄로 보여 준다.
- 미리 듣기는 받는 사람에게 들릴 문장 그대로 읽는다.
- **주행 중에는 열지 않는다.** 휴대폰이 모임 주행 중이고 움직이고 있으면 “정차한 뒤에 고칠 수 있어요”만 보여 준다.

### 동기화

- 저장하면 계정 서버에 올리고, 차량 앱은 켤 때 · 정차할 때 · 서버 알림을 받을 때 다시 받는다 (`MyMessageRepository.refresh`).
- 차량 앱은 받아서 보여 주기만 한다. 차량에서는 만들기·고치기·지우기·순서 바꾸기를 하지 않는다.

## 3. 차량 — 내 메시지 고르기 (구현)

- 주행 화면 아래쪽 막대의 **‘내 메시지’** 버튼 → 지도 아래쪽에 큰 버튼 6개(3×2)가 뜬다. 스크롤 없음.
- 누르면 바로 현재 모임에 보낸다. 버튼이 ‘보냈어요 ✓’로 바뀌고, 자막과 모임 소식에 남은 뒤 패널이 닫힌다.
- 10초 동안 아무것도 안 누르면 저절로 닫힌다(알림 카드와 같은 규칙).
- 같은 메시지는 30초 동안 다시 보낼 수 없고(버튼이 흐려짐), 1분에 4번까지 보낼 수 있다(기본 메시지·음성 메시지 포함).
- 상황 공유 알림이나 투표가 오면 패널을 닫고 알림을 먼저 보여 준다.
- 지도 · 다음 집결지 · 모임 현황 · 모임 소식 배치는 바꾸지 않았다. 패널은 지도 위에 잠깐 뜨는 층이다.

## 4. 받는 차 — 읽어 주기 흐름 (구현)

```
GroupChannel.incoming
  └ Custom(보낸 사람, 문장)
      ├ 모임 소식에 추가 (‘내 메시지’ 표시)
      ├ 같은 사람이 같은 말을 1분 안에 또 보냈으면 → 다시 읽지 않음 (RepeatFilter)
      ├ ‘메시지 읽어 주기’ 끔 → 자막만
      └ 켬 → VoiceQueue 에 넣기 (우선순위: 안전 > 모임 안내 > 메시지 > 내 확인)
             ├ 한 번에 하나만 읽는다 (겹쳐 재생 없음)
             ├ 내비 길 안내 음성이 나오는 중이면 끝날 때까지 기다린다 (최대 20초, 넘으면 자막만)
             └ 읽는 동안 자막에 보낸 사람 얼굴과 문장을 함께 보여 준다
```

- 내비 안내 중인지는 안드로이드 공개 API(`AudioManager.getActivePlaybackConfigurations`)로 길 안내 용도
  (`USAGE_ASSISTANCE_NAVIGATION_GUIDANCE`) 재생이 있는지만 본다. 차량의 음성 엔진 설정은 바꾸지 않았다.
- 메시지는 3개까지만 기다리게 하고, 넘치면 오래된 것부터 자막·소식으로만 남긴다.
- 안전 안내(졸려요 → 쉬어가기 제안)는 ‘메시지 읽어 주기’를 꺼도 읽는다. 투표를 말로 답하는 흐름과 이어져 있기 때문이다.

### 휴대폰에서 받을 때 (설계)

- 앱이 화면에 떠 있을 때만 앱이 직접 읽는다.
- 백그라운드에서는 OS 알림(글자)으로만 보낸다. iOS·안드로이드 모두 백그라운드 음성 재생이 되는 것을 전제로 하지 않는다.
  (안드로이드에서 주행 모드 포그라운드 서비스로 읽게 하려면 사용자가 켜야 하고, 그 전에는 알림만.)

## 5. 정책

| 구분 | 규칙 | 코드 |
|---|---|---|
| 개수 | 내 메시지 최대 6개 | `QuickMessagePolicy.MAX_MESSAGES` |
| 길이 | 2~20자 (음성으로 보낼 때 40자) | `MIN_LENGTH`, `MAX_LENGTH`, `MAX_SPOKEN_LENGTH` |
| 글자 | 한글·영문·숫자·기본 문장부호만. 이모지는 아이콘으로 고른다 (차량마다 글꼴이 달라서) | `UNSUPPORTED_CHARACTER` |
| 개인정보 | 전화번호·링크는 보낼 수 없다 | `CONTACT_INFO` |
| 위험 표현 | 과속·추월·신호 무시를 권하거나 재촉하는 말, 욕설 | `UNSAFE` (목록은 검토용 초안) |
| 중복 | 같은 문장 두 개 금지, 기본 메시지와 같은 문장 금지 | `DUPLICATE`, `SAME_AS_DEFAULT` |
| 보내기 | 두 번 눌림 2초, 같은 메시지 30초, 1분에 4번 | `SendGuard` |
| 받기 | 같은 사람·같은 말 1분 안 반복은 다시 읽지 않음 | `RepeatFilter` |
| 범위 | 현재 모임 참여자에게만 (모임이 끝나면 위치와 함께 삭제) | `GroupChannel` |

## 6. 이번에 구현한 범위

| 항목 | 상태 | 비고 |
|---|---|---|
| 차량: 내 메시지 고르기·보내기·완료 표시·중복 방지 | 구현 | 시연 데이터 6개 |
| 차량: 받은 메시지 읽어 주기·자막·소식, 읽어 주기 켬/끔 | 구현 | |
| 음성 순서(우선순위·겹침 방지·내비 안내 대기) | 구현 | `VoiceQueue` |
| 문장 검사·보내기 제한·반복 거르기 | 구현 + 단위 테스트 | 휴대폰 앱에서도 같은 규칙 |
| 같은 전송 통로(기본·내 메시지·음성) | 구현 | 시연용 `DemoGroupChannel` |
| 휴대폰 관리 화면 | 설계 | 휴대폰 앱 개발 때 |
| 계정 저장·동기화 서버 | 인터페이스만 | `MyMessageRepository` |
| 실제 차량 간 전송 | 인터페이스만 | 동기화 서버(WebSocket) 붙일 자리 |

## 7. 실차(Pleos 에뮬레이터)에서 확인할 것

- 내비 길 안내 음성이 다른 앱에 `USAGE_ASSISTANCE_NAVIGATION_GUIDANCE` 로 보이는지 (안 보이면 대기 없이 순서만 지킨다)
- Pleos TTS 가 끝났을 때 이벤트(onDone/onStop)가 매번 오는지 (안 오면 글자 수로 계산한 시간 뒤 다음으로 넘어간다)
